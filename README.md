# WirelessStatus · 鼠标电量小窗

> 给罗技无线设备用的 Windows 桌面小工具：常驻托盘，点一下弹出小卡片，
> 一屏看完所有配对设备的电量，还能把电量胶囊**真正嵌进任务栏**。

## 它解决什么

罗技的 G HUB / Options+ 又大又慢，只在它自己开着的窗口里才显示电量；
Windows 自带的蓝牙电量只对蓝牙直连设备有效，走 USB 接收器的鼠标完全看不到。
结果就是：**鼠标突然没电关机，你事先一点提示都没有。**

WirelessStatus 直接跟罗技接收器说 HID++ 2.0 协议，把电量、DPI 读出来，
塞进一个点开就走的托盘小窗里。它同时做三件事：

* **一屏看全部** —— 接收器上挂了几个设备就列几个，不用切来切去；
* **任务栏贴片** —— 电量直接长在任务栏上，余光就能扫到；
* **电量历史** —— 记下每天的变化，能看出「这只电池还能撑几天」。

## 功能

| | |
|---|---|
| **设备列表** | 所有配对设备 + 电量 + 在线状态；多设备按索引全部列出 |
| **设备详情** | 电量圆环、使用时长、DPI 调节、电量历史曲线 |
| **任务栏电量贴片** | 真正 `SetParent` 到 `Shell_TrayWnd`；**扁平单行**「环形电量图标 + 数值」，多设备并列 |
| **悬停显示型号** | 鼠标停在贴片上弹出气泡：设备名 + 型号 / 连接方式 / 电量 / 今日用电 |
| **溢出面板避让** | 「显示隐藏的图标」弹出时窗口整体上移，两者互不遮挡、不漂移 |
| **电量历史** | 24 小时 / 7 日 / 30 日三档聚合，换电池自动打标 |
| **使用时长** | 500 ms 采样光标与按键，跨午夜结转，休眠不计 |
| **DPI 调节** | 读写 HID++ `0x2201`，写完回读确认，失败说明具体原因 |
| **开机自启** | HKCU Run（带 `--silent`），源码 / exe 两种形态自愈，启动全程静默 |
| **单实例** | 重复启动只唤起已有窗口；开机时的第二个实例会**悄悄退出**，绝不弹窗 |

## 界面

### 设备列表

一台设备就是一个紧凑小卡片，设备多了往上长（超过 760 px 才内部滚动），
**不留空白**。

### 设备详情

电量圆环、今日已运行、DPI 滑块与电量历史曲线。历史图是 Canvas 手画的，
不引图表库。

### 任务栏电量贴片

紧贴「显示隐藏的图标」箭头左侧，**不是覆盖在任务栏上的悬浮窗**，而是真的
`SetParent` 成了任务栏的子窗口：

这意味着它会跟着任务栏一起绘制、一起自动隐藏、一起按 DPI 缩放，
Alt+Tab 里看不到它，也不产生任务栏按钮、点它不抢焦点。

样式是**扁平单行**的（对齐 LiteMonitor 的任务栏显示，但只占一行）：

```
(环) 90%   (环) 45%
```

* 图标是**环形电量表**：灰底环 + 绿色进度弧（按这台设备自己的电量），
  环内一枚绿色闪电；
* 数值粗体等宽数字，按电量分档染色（≥50 绿 / ≥20 琥珀 / <20 红）；
* 多设备**并列**在同一行，不换行；超过 4 台收进「+N」；
* 没有底色块、没有描边、没有圆角胶囊 —— 窗口底色就是任务栏采样色，
  边界看不见。

鼠标停在任意一台设备上，会弹出一个独立的 Win32 气泡：

```
罗技 M350 Wireless Mouse
USB 接收器 · 电量 90% · 今日用电 7%
```

**为什么气泡不是网页里的 tooltip**：贴片窗只有 26 逻辑像素高、还被
`SetWindowRgn` 裁过，WebView2 画不出窗口边界之外的东西 —— 网页 tooltip
一弹就被裁掉，屏幕上什么都不会出现。所以提示走的是 `tipwindow.py` 里
那个独立顶层窗（`WS_EX_NOACTIVATE`，不抢焦点、不激活）。

## 快速开始

### 直接用 exe

从 [Releases](https://github.com/LittleDoubee/wireless-status/releases) 下载 `WirelessStatus.exe`，双击即可。
目标机器**不需要装 Python**，首次运行会在 exe 同目录生成四个 json 配置。

### 从源码跑

```bat
python -m pip install --no-deps pywebview
python -m pip install pywin32 hidapi

start.bat
```

> `--no-deps` 是必须的：不带它 pip 会去装 pyobjc（macOS 专用），Windows 上直接报
> `PyObjC requires macOS to build` 然后整个安装失败。

双击 `start.bat` 是**静默启动**（无窗口、无黑框，只在托盘出现图标）。
想直接看到界面：

```bat
python main.py --show
```

### 启动开关

| 参数 | 行为 |
|---|---|
| （无） | 静默：只在托盘出现，不显示窗口 |
| `--silent` | 同上，**开机自启注册表里写的就是这条** —— 显式声明"这次是被开机拉起的" |
| `--show` | 调试用，起来就显示主窗；第二次启动时会唤起已有实例的窗口 |

> 不带 `--show` 时，重复启动**什么都不做**（不弹窗、不唤窗、不报错）。
> 开机自启从来不带 `--show`，所以开机时不会自己弹出任何窗口。

### 重新生成图标

```bat
python tools\make_icon.py            :: 写 icon/app.ico + icon/app.png
python tools\make_icon.py --preview  :: 额外出一张各尺寸对照图
```

图标是**环形电量表**：灰底环（`#7F8083`）+ 绿色进度弧（`#14D448`）+
环内绿色闪电，**透明背景、不带方块底板**。16/20/24 这几档会自动加粗环、
拉宽闪电，否则缩下去只剩一粒绿点。

### 自测

```bat
python selftest.py        :: 172 项，全离线，不需要插鼠标
python selftest.py -v     :: 看每一项名字
```

## 支持的设备

* **通过 Nano 接收器（USB）接入的 HID++ 2.0 鼠标**。已实测：**M350 Wireless Mouse**
  （PID `B021`，接收器 PID `C52F`）。
* 型号**不硬编码**：运行时读 HID++ `0x0005`（DeviceName）与 `0x0003`
  （DeviceInformation）拿真实产品名与 PID。
* DPI（`0x2201`）与电量（`0x1000` / `0x1004`）能力都按设备**实际枚举到的特性**
  判断，不按型号猜。

**不支持**：蓝牙直连、USB 线直连（本工具走接收器通道）。只有短报文接口
（report ID `0x10`）的接收器读不了 `0x2201`。

## 实现要点

几个踩过的坑，写下来给以后的自己（也给别人）：

### 开机自启为什么不会再弹窗

三处一起改才彻底：

1. **注册表只能有一条**。旧版本除 `WirelessStatus` 之外还写过一个别名
   `MouseOverlay`，两条都指向同一份脚本 —— 开机时 explorer 起两个进程，
   第二个撞单实例锁。`autostart.prune_legacy()` 启动时清掉指向本程序的
   历史别名（只删确认是本程序的，别人的同名项不动）。
2. **命令行带 `--silent`**。开机路径是"存在即静默"，写进注册表而不是
   只靠程序默认值 —— 以后默认改了也不会退化成弹窗。
3. **二次启动不再唤窗、不再弹框**。老代码拿不到锁时会 `ShowWindow` 把已有
   窗口顶出来，唤窗失败还兜底弹 `MessageBox("已经在运行了")` —— 开机时
   必然走到那一支。现在只有显式带 `--show` 才唤窗，其余静默退出。
   启动失败也只落盘、不弹窗（`_report_fatal(silent=...)`）。

唤窗本身也从 `PostMessage` 换成了**命名事件**：主窗的 WndProc 属于
pywebview（WinForms），外部挂不上自己的消息处理，发自定义消息进去会被
默认分支吃掉。事件是纯 Win32、跨进程、不需要窗口句柄。

### 悬停气泡为什么不能用网页 tooltip

贴片窗只有 26 逻辑像素高，而且被 `SetWindowRgn` 裁成内容形状。
**WebView2 画不出窗口之外的东西** —— 网页里的 tooltip 只要往上弹出窗口
边界就被裁掉，屏幕上什么都不显示（这就是"实现了但用不了"的根因）。

所以提示改成独立顶层窗（`tipwindow.py`）：自己的线程 + 自己的消息泵，
`WS_POPUP | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TOPMOST`，
GDI 自绘圆角气泡。三个必须保留的细节：

* `CreateWindowEx` 的 style **必须显式给 `WS_POPUP`**：传 0 时 pywin32
  会退回"带标题栏的默认窗口"，弹出的是一条带 caption 的白条；
* `win32gui` **没有** `CreateFont`，要走 ctypes 调 `gdi32.CreateFontW`
  并声明完整 14 个 argtypes（不声明时 ctypes 按调用现场猜参数个数，多传
  一个就 TypeError）；
* 跨线程只能 `PostMessage`，不能直接 `SetWindowPos`。

### 任务栏贴片为什么能「真嵌进去」

`SetParent` 成 `Shell_TrayWnd` 的子窗口 + `WS_CHILD`（去掉 `WS_POPUP`）。
关键是**先设几何再裁形状** —— `SetWindowRgn` 的区域是窗口坐标，窗口被
`SetWindowPos` 改大改小时区域不会跟着缩放，先裁会「右边缺一块」。

扁平样式下 `PILL_RADIUS = 0`，`clip_round_rect` 会**清掉区域**
（`SetWindowRgn(hwnd, None)`）让窗口保持直角：任何圆角都会在四角露出
一点任务栏本身，颜色对不齐时反而显出一圈缺口。

### 贴片底色为什么用渐变而不是纯色

Win11 任务栏是亚克力材质，颜色跟着壁纸走，而且**横向有明显渐变**。实测
通知区附近：

```
x=1700 → (209, 221, 221)
x=1850 → (216, 229, 228)
x=1900 → (224, 236, 233)
x=2000 → (230, 234, 234)
```

90 像素宽的贴片就横跨这段，差 8~20 级。填一个纯色，无论取哪个采样点，
总有一条边对不上 —— 肉眼就是「任务栏上一块淡淡的方印子」。

所以 `winui.taskbar_background_profile()` 沿贴片**自己的横向区间**采
7 个点（纵向取贴片上方/下方那两条空白，避开文字笔画），前端画成
`linear-gradient(to right, ...)`。

> **已知残余色差**：显示器色彩管理对窗口合成做的色彩变换与任务栏不是同
> 一条路径，同一个 8bit 值落到屏幕上会差 1~4 级（实测任务栏 (222,234,234)
> vs 窗口 (216,234,234)）。试过按实测差值做闭环补偿，但那个变换既不是
> 加性偏移、也不完全单调，迭代会在目标两侧来回跳（会越修越花），所以
> **不补偿**。渐变采样点误差落在 1~2 级，正常视距下看不出边界。

### 只有圆环没有底板

图标按用户给的参考图重画：**透明背景**上只有「灰底环 + 绿色进度弧 +
环内闪电」，没有深色圆角方块底板。四角 alpha 必须为 0 ——
`selftest` 里有断言盯着（`test_icon_corners_transparent`），
换成带底板的图标会直接失败。

小尺寸（16/20/24）单独处理：环加粗到外径的 15.5%、闪电横向拉宽 1.35 倍，
否则缩下去灰底环被绿弧盖掉、只剩一粒绿点。

### 「已运行」为什么以 5 秒为断点

光标停止移动或松开按键后，计时再平滑走满 5 秒才停。收段末端算到
`min(now, last_active + IDLE)`，`today()` 也封顶到此刻 —— 三处口径不一致
就是「数字先冻住、过几秒突然 +5、偶尔还往回跳」的成因。

### 主窗为什么不会漂

* 底边钉死在任务栏上沿（`y = bar_top - h - gap`），窗口只往上长，
  切换设备改变高度时底边不动；
* `x` 算出后锁进 `_fixed_x` 复用 —— 「按图标中心」与「按通知区中心」差 40 多
  像素，不锁的话每次点托盘图标都横向挪一次；
* 「已应用高度」与「前端上报高度」分开存，避免首帧误报把窗口压塌。

```
  tipwindow.py        贴片悬停气泡（独立 Win32 顶层窗 + GDI 自绘）
  devices.py          设备抽象（DeviceProvider / HidppProvider）

  mouse_source.py     罗技 HID++ 2.0 通信（接收器枚举、设备 probe、DPI/电量）

  tray.py             系统托盘（独立线程 + 消息泵）

  selftest.py         离线自测（172 项）

  icon/               应用图标与设备图标
  tools/make_icon.py  图标生成脚本（环形电量表，多尺寸 ico）
  docs/REFERENCE.md   完整手册（打包、排查、配置项、电量精度）
```

## 已知限制

* 只支持走 USB 接收器的 HID++ 2.0 设备，蓝牙直连与有线直连未对接。
* 只有电压特性（`0x1001`）的设备显示「不支持」—— 电压换算百分比各机型不一致，
  硬换算出来的数字是骗人的。
* 使用时长统计的是**全系统的键鼠动作**，不是这只鼠标自己的传感器数据
  （Windows 不提供后者）。
* 装了搜狗输入法时，它注入到 WebView2 的 TSF 组件会往**进程工作目录**写
  `debug.log`（内容是 `SGRenderLog`，与本程序无关）。本程序启动时已把 CWD
  挪到 `%LOCALAPPDATA%\WirelessStatus\runtime\`，所以 exe 旁边不会出现这个文件。
