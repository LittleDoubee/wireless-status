# WirelessStatus · 鼠标电量小窗

> 给罗技无线设备用的 Windows 桌面小工具：常驻托盘，点一下弹出小卡片，
> 一屏看完所有配对设备的电量，还能把电量胶囊**真正嵌进任务栏**。

## 它解决什么

罗技的 G HUB / Options+ 又大又慢，只在它自己开着的窗口里才显示电量；
Windows 自带的蓝牙电量只对蓝牙直连设备有效，走 USB 接收器的鼠标完全看不到。
结果就是：**鼠标突然没电关机，你事先一点提示都没有。**

WirelessStatus 直接跟罗技接收器说 HID++ 2.0 协议，把电量、DPI 读出来，
塞进一个点开就走的托盘小窗里。它同时做三件事：

* **一屏看全部** —— 接收器上挂了几个设备就列几个，不用切来切去；
* **任务栏贴片** —— 电量直接长在任务栏上，余光就能扫到；
* **电量历史** —— 记下每天的变化，能看出「这只电池还能撑几天」。

## 功能

| | |
|---|---|
| **设备列表** | 所有配对设备 + 电量 + 在线状态；多设备按索引全部列出 |
| **设备详情** | 电量圆环、使用时长、DPI 调节、电量历史曲线 |
| **任务栏电量贴片** | 真正 `SetParent` 到 `Shell_TrayWnd`，跟着任务栏绘制/隐藏/缩放 |
| **电量历史** | 24 小时 / 7 日 / 30 日三档聚合，换电池自动打标 |
| **使用时长** | 500 ms 采样光标与按键，跨午夜结转，休眠不计 |
| **DPI 调节** | 读写 HID++ `0x2201`，写完回读确认，失败说明具体原因 |
| **开机自启** | HKCU Run，源码 / exe 两种形态自愈 |
| **单实例** | 重复启动只唤起已有窗口，不起第二个进程 |

## 界面

### 设备列表

一台设备就是一个紧凑小卡片，设备多了往上长（超过 760 px 才内部滚动），
**不留空白**。

### 设备详情

电量圆环、今日已运行、DPI 滑块与电量历史曲线。历史图是 Canvas 手画的，
不引图表库。

### 任务栏电量贴片

紧贴「显示隐藏的图标」箭头左侧，**不是覆盖在任务栏上的悬浮窗**，而是真的
`SetParent` 成了任务栏的子窗口：

这意味着它会跟着任务栏一起绘制、一起自动隐藏、一起按 DPI 缩放，
Alt+Tab 里看不到它，也不产生任务栏按钮、点它不抢焦点。

## 快速开始

### 直接用 exe

从 [Releases](../../releases) 下载 `WirelessStatus.exe`，双击即可。
目标机器**不需要装 Python**，首次运行会在 exe 同目录生成四个 json 配置。

### 从源码跑

```bat
python -m pip install --no-deps pywebview
python -m pip install pywin32 hidapi

start.bat
```

> `--no-deps` 是必须的：不带它 pip 会去装 pyobjc（macOS 专用），Windows 上直接报
> `PyObjC requires macOS to build` 然后整个安装失败。

双击 `start.bat` 是**静默启动**（无窗口、无黑框，只在托盘出现图标）。
想直接看到界面：

```bat
python main.py --show
```

### 自测

```bat
python selftest.py        :: 131 项，全离线，不需要插鼠标
python selftest.py -v     :: 看每一项名字
```

## 支持的设备

* **通过 Nano 接收器（USB）接入的 HID++ 2.0 鼠标**。已实测：**M350 Wireless Mouse**
  （PID `B021`，接收器 PID `C52F`）。
* 型号**不硬编码**：运行时读 HID++ `0x0005`（DeviceName）与 `0x0003`
  （DeviceInformation）拿真实产品名与 PID。
* DPI（`0x2201`）与电量（`0x1000` / `0x1004`）能力都按设备**实际枚举到的特性**
  判断，不按型号猜。

**不支持**：蓝牙直连、USB 线直连（本工具走接收器通道）。只有短报文接口
（report ID `0x10`）的接收器读不了 `0x2201`。

## 实现要点

几个踩过的坑，写下来给以后的自己（也给别人）：

### 任务栏贴片为什么能「真嵌进去」

`SetParent` 成 `Shell_TrayWnd` 的子窗口 + `WS_CHILD`（去掉 `WS_POPUP`）。
关键是**先设几何再裁形状** —— `SetWindowRgn` 的区域是窗口坐标，窗口被
`SetWindowPos` 改大改小时区域不会跟着缩放，先裁会「右边缺一块」。

形状靠 `SetWindowRgn` + `CreateRoundRectRgn` 裁，不是靠透明：
pywebview 在 WinForms + WebView2 上的 `transparent=True` 并不做逐像素透明，
实测就是一整块不透明矩形。

贴片窗**不套毛玻璃**：DWM 的亚克力效果按窗口包围盒画，不认 region 裁出来的
形状，套上去胶囊四角外侧会冒出一圈深灰。

### 贴片底色跟任务栏走

Win11 任务栏是亚克力材质，颜色随壁纸和采样点浮动，写死一个 `#f7f8fa` 就会
变成「贴上去的白补丁」。所以运行时 `BitBlt` 抓任务栏、跳过半透明与图标笔画、
直方图取众数，再据此推导胶囊底色（提亮 2~4 级）与边框。

必须**只在贴片左侧采样**：右侧 80 px 会落进 `TrayNotifyWnd` 的中性灰底，
把众数拉偏 20 级。

### 「已运行」为什么以 5 秒为断点

光标停止移动或松开按键后，计时再平滑走满 5 秒才停。收段末端算到
`min(now, last_active + IDLE)`，`today()` 也封顶到此刻 —— 三处口径不一致
就是「数字先冻住、过几秒突然 +5、偶尔还往回跳」的成因。

### 主窗为什么不会漂

* 底边钉死在任务栏上沿（`y = bar_top - h - gap`），窗口只往上长，
  切换设备改变高度时底边不动；
* `x` 算出后锁进 `_fixed_x` 复用 —— 「按图标中心」与「按通知区中心」差 40 多
  像素，不锁的话每次点托盘图标都横向挪一次；
* 「已应用高度」与「前端上报高度」分开存，避免首帧误报把窗口压塌。

## 已知限制

* 只支持走 USB 接收器的 HID++ 2.0 设备，蓝牙直连与有线直连未对接。
* 只有电压特性（`0x1001`）的设备显示「不支持」—— 电压换算百分比各机型不一致，
  硬换算出来的数字是骗人的。
* 使用时长统计的是**全系统的键鼠动作**，不是这只鼠标自己的传感器数据
  （Windows 不提供后者）。
* 装了搜狗输入法时，它注入到 WebView2 的 TSF 组件会往**进程工作目录**写
  `debug.log`（内容是 `SGRenderLog`，与本程序无关）。本程序启动时已把 CWD
  挪到 `%LOCALAPPDATA%\WirelessStatus\runtime\`，所以 exe 旁边不会出现这个文件。
