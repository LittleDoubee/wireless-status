# Wireless Status

> 常驻 Windows 任务栏的**无线外设电量监视器**。
> 不绑定品牌、不绑定设备类型 —— 鼠标、键盘、耳机、手柄都走同一套界面。

## 它解决什么

无线外设最烦的瞬间：**用到一半突然断电**，而系统事先一声不吭。

Windows 自带的蓝牙电量只覆盖蓝牙直连设备，插 USB 接收器的那些（罗技、雷柏、
戴尔……）完全不显示；厂商自带的驱动面板又大又慢，还只在它自己开着的窗口里
才看得到电量。

Wireless Status 直接跟接收器对话，把电量和设备信息读出来，然后做三件事：

* **一屏看全部** —— 接收器上挂了几个设备就列几个，不用切来切去；
* **任务栏贴片** —— 电量直接长在任务栏上，余光就能扫到；
* **电量历史** —— 记下每天的变化，能看出「这块电池还能撑几天」。

## 功能

| | |
|---|---|
| **设备列表** | 所有配对设备 + 电量 + 在线状态；多设备全部列出，按类型区分 |
| **设备详情** | 电量圆环、使用时长、电量历史曲线；有 DPI 能力的设备额外显示 DPI 调节 |
| **任务栏电量贴片** | 真正 `SetParent` 到 `Shell_TrayWnd`；**扁平单行**「设备图标 + 数值」，多设备并列 |
| **悬停设备信息** | 鼠标停在贴片上弹出气泡：设备名 + 型号 / 连接方式 / 电量 / 今日用电 |
| **溢出面板避让** | 「显示隐藏的图标」弹出时窗口整体上移，两者互不遮挡、不漂移 |
| **电量历史** | 24 小时 / 7 日 / 30 日三档聚合，换电池自动打标 |
| **使用时长** | 500 ms 采样光标与按键，跨午夜结转，休眠不计 |
| **开机自启** | HKCU Run（带 `--silent`），源码 / exe 两种形态自愈，启动全程静默 |
| **单实例** | 重复启动只唤起已有窗口；开机时的第二个实例会**悄悄退出**，绝不弹窗 |

## 支持的设备类型

设备类型由**运行时读取的型号名**推断（`devices.guess_kind`），不按 USB
PID 硬编码 —— 所以同一种设备的不同型号、甚至将来别家的设备都能落进对应
分类，不需要改代码。

| 类型 | 图标 | 电量 | 使用时长 | 电量历史 | DPI | 状态 |
|---|---|---|---|---|---|---|
| **鼠标** | `mouse` | ✅ | ✅ | ✅ | ✅ | 已实测 |
| **键盘** | `keyboard` | ✅ | ✅ | ✅ | — | 待接入 |
| **耳机** | `headset` | ✅ | ✅ | ✅ | — | 待接入 |
| **手柄** | `gamepad` | ✅ | ✅ | ✅ | — | 待接入 |
| **其它** | `unknown` | ✅ | ✅ | ✅ | — | 兜底 |

说明：

* **电量 / 使用时长 / 电量历史**是**类型无关**的通用能力 —— 协议层拿到的是
  "某台设备现在的电量"，什么设备都一样，所以新类型接进来立刻就能用；
* **DPI** 只有指针类设备（鼠标）有意义，键盘/耳机/手柄的详情页会自动隐藏
  这一块，不会显示一个没用的滑块；
* **待接入**指的是"设备枚举与命名规则还没用真机验证过"，不是"功能不存在"。
  插上设备后如果分类不对，改 `devices.KIND_HINTS` 里的关键词即可。

## 界面

### 设备列表

一台设备就是一个紧凑小卡片，设备多了往上长（超过 760 px 才内部滚动），
**不留空白**。卡片左侧是设备类型图标，右侧是电量与在线状态。

### 设备详情

电量圆环、今日已运行、电量历史曲线（Canvas 手画，不引图表库）。
只有报出 DPI 能力的设备才显示 DPI 滑块。

### 任务栏电量贴片

紧贴「显示隐藏的图标」箭头左侧，**不是覆盖在任务栏上的悬浮窗**，而是真的
`SetParent` 成了任务栏的子窗口：

这意味着它会跟着任务栏一起绘制、一起自动隐藏、一起按 DPI 缩放，
Alt+Tab 里看不到它，也不产生任务栏按钮、点它不抢焦点。

样式是**扁平单行**的（对齐 LiteMonitor 的任务栏显示，但只占一行）：

```
(鼠标) 90%   (耳机) 45%   (键盘) 78%
```

* 图标是**设备类型**图标（鼠标 / 键盘 / 耳机 / 手柄），不是电量环 ——
  电量已经由数字表达，图标负责一眼区分"这一格是什么设备"；
* 数值粗体等宽数字，按电量分档染色，色值对齐 LiteMonitor：
  `#008040` 安全 / `#B57500` 警告 / `#C03030` 严重；
* 多设备**并列**在同一行，不换行；超过 4 台收进「+N」；
* 没有底色块、没有描边、没有圆角胶囊 —— 窗口底色随任务栏采样，边界看不见。

鼠标停在任意一台设备上，会弹出一个独立的 Win32 气泡：

```
罗技 M350 Wireless Mouse
USB 接收器 · 电量 90% · 今日用电 7%
```

**为什么气泡不是网页里的 tooltip**：贴片窗只有 26 逻辑像素高、还被
`SetWindowRgn` 裁过，WebView2 画不出窗口边界之外的东西 —— 网页 tooltip
一弹就被裁掉，屏幕上什么都不会出现。所以提示走的是 `tipwindow.py` 里
那个独立顶层窗（`WS_EX_NOACTIVATE`，不抢焦点、不激活）。

## 快速开始

### 直接用 exe

从 [Releases](https://github.com/LittleDoubee/wireless-status/releases) 下载 `WirelessStatus.exe`，双击即可。
目标机器**不需要装 Python**，首次运行会在 exe 同目录生成四个 json 配置。

### 从源码跑

```bat
python -m pip install --no-deps pywebview
python -m pip install pywin32 hidapi

start.bat
```

> `--no-deps` 是必须的：不带它 pip 会去装 pyobjc（macOS 专用），Windows 上直接报
> `PyObjC requires macOS to build` 然后整个安装失败。

双击 `start.bat` 是**静默启动**（无窗口、无黑框，只在托盘出现图标）。
想直接看到界面：

```bat
python main.py --show
```

### 启动开关

| 参数 | 行为 |
|---|---|
| （无） | 静默：只在托盘出现，不显示窗口 |
| `--silent` | 同上，**开机自启注册表里写的就是这条** —— 显式声明"这次是被开机拉起的" |
| `--show` | 调试用，起来就显示主窗；第二次启动时会唤起已有实例的窗口 |

> 不带 `--show` 时，重复启动**什么都不做**（不弹窗、不唤窗、不报错）。
> 开机自启从来不带 `--show`，所以开机时不会自己弹出任何窗口。

### 从 DSH 终端启动会跟着 DSH 一起退出 —— 用 launcher

在 DSH（DeepSeek Harness）的终端里直接跑 `python main.py`，进程会落在 DSH 的
**Job Object** 里；DSH 一关，那个 Job 被关闭，进程**跟着被杀**。用户看到的
现象就是"程序莫名其妙闪退"，而且退出时机和 DSH 完全一致。

`start.bat` 已经改成走脱离通道（`launcher.py --start`）：它用 **Task
Scheduler** 拉起进程，父进程是 `svchost`，不在调用者的进程树里，所以：

* 从 DSH 终端、CMD、PowerShell、IDE 里启动都**不会**被连带杀掉；
* 手动执行也行：

```bat
python launcher.py --start          :: 脱离启动（静默）
python launcher.py --start --show   :: 脱离启动并直接显示窗口
```

> 开机自启（`HKCU\...\Run`）由 explorer 拉起，本来就独立于 DSH，不受影响。

### 重新生成图标

```bat
python tools\make_icon.py            :: 写 icon/app.ico + icon/app.png
python tools\make_icon.py --preview  :: 额外出一张各尺寸对照图
```

应用图标是**环形电量表**（灰底环 + 绿色进度弧 + 环内闪电，透明背景）——
这是**程序自己**的形象，和贴片里表示设备类型的图标是两回事。

### 自测

```bat
python selftest.py        :: 175 项，全离线，不需要插设备
python selftest.py -v     :: 看每一项名字
```

## 设备接入

### 协议

当前实现走**罗技 HID++ 2.0**（Nano / Unifying / Bolt 接收器）。

**不支持**：蓝牙直连、USB 线直连。只有短报文接口（report ID `0x10`）的
接收器读不了 `0x2201`（DPI）。

### 型号与类型不硬编码

* 型号：运行时读 HID++ `0x0005`（DeviceName）与 `0x0003`（DeviceInformation）
  拿真实产品名与 PID；
* 类型：由型号名里的关键词推断（`devices.KIND_HINTS`），判不出来的按鼠标处理
  （因为目前只有指针类设备做了真机验证，误判成耳机更糟）；
* 能力：电量（`0x1000` / `0x1004`）与 DPI（`0x2201`）都按设备**实际枚举到的
  特性**判断，不按型号猜。

### 加一种新设备类型

1. 在 `devices.py` 的 `KIND_*` 加常量、`KIND_ICON` 加图标名、`KIND_LABEL`
   加中文名；
2. 在 `KIND_HINTS` 里加型号关键词；
3. 在 `icon/` 放一个同名 SVG（`viewBox="0 0 24 24"`、
   `stroke="currentColor"`、`fill="none"`，参考现有的 Lucide 图标）。

前端的设备图标、贴片图标、详情页条件显示都跟着这几个常量走，**不用改 JS**。

## 实现要点

几个踩过的坑，写下来给以后的自己（也给别人）：

### 开机自启为什么不会再弹窗

三处一起改才彻底：

1. **注册表只能有一条**。同一个程序在 `Run` 下被注册两条时，开机 explorer 会
   起两个进程，第二个撞单实例锁。`autostart.prune_legacy()` 启动时遍历
   `Run`，凡是**命令行指向本程序**、但值名不是规范名的项一律删掉。
   按命令行内容判断而不是"写死旧名字" —— 前者改名多少次都不会漏，
   后者每改一次名就得回来补一次。
2. **命令行带 `--silent`**。开机路径是"存在即静默"，写进注册表而不是
   只靠程序默认值 —— 以后默认改了也不会退化成弹窗。
3. **二次启动不再唤窗、不再弹框**。老代码拿不到锁时会 `ShowWindow` 把已有
   窗口顶出来，唤窗失败还兜底弹 `MessageBox("已经在运行了")`。现在只有显式
   带 `--show` 才唤窗，其余静默退出。启动失败也只落盘、不弹窗。

唤窗本身用的是**命名事件**而不是 `PostMessage`：主窗的 WndProc 属于
pywebview（WinForms），外部挂不上自己的消息处理，发自定义消息进去会被
默认分支吃掉。

### 悬停气泡为什么不能用网页 tooltip

两层原因，缺一条都不行：

1. 贴片窗只有 26 逻辑像素高，还被 `SetWindowRgn` 裁成内容形状 ——
   **WebView2 画不出窗口之外的东西**，网页 tooltip 一弹就被裁掉；
2. 更要命的是：贴片窗是 `Shell_TrayWnd` 的**子窗口** + `WS_EX_NOACTIVATE`，
   实测在这种状态下 WebView2 **收不到 mouseenter / mouseleave**
   （往 `set_pill_hover` 里打日志，从头到尾一次都没有）。
   所以"网页事件驱动"这套实现看起来对、实际永远不生效。

修法：气泡改成 `tipwindow.py` 的独立 Win32 顶层窗，**触发**也交给后端 ——
命令泵每 0.2s 量一次真实光标位置，判断指针在不在贴片矩形里、落在哪个设备位
（前端通过 `set_pill_segments` 上报每台设备的横向区间）。这套思路和
「指针离开自动收窗」完全一致，跟 DOM 事件一点关系都没有。

三个容易再踩的细节：

* `CreateWindowEx` 的 style **必须显式给 `WS_POPUP`**，传 0 时 pywin32 会
  退回"带标题栏的默认窗口"，弹出的是一条带 caption 的白条；
* `win32gui` **没有** `CreateFont` —— 走 ctypes 调 `gdi32.CreateFontW`，
  并声明完整 14 个 `argtypes`（不声明时 ctypes 按调用现场猜参数个数，
  多传一个就 `TypeError: this function takes 12 arguments (14 given)`）；
* 跨线程只能 `PostMessage`（`WM_TIP_SHOW` / `WM_TIP_HIDE`），不能直接
  `SetWindowPos`。

### 任务栏贴片为什么能「真嵌进去」

`SetParent` 成 `Shell_TrayWnd` 的子窗口 + `WS_CHILD`（去掉 `WS_POPUP`）。
关键是**先设几何再裁形状** —— `SetWindowRgn` 的区域是窗口坐标，窗口被
`SetWindowPos` 改大改小时区域不会跟着缩放，先裁会「右边缺一块」。

扁平样式下 `PILL_RADIUS = 0`，`clip_round_rect` 会**清掉区域**
（`SetWindowRgn(hwnd, None)`）让窗口保持直角：任何圆角都会在四角露出
一点任务栏本身，颜色对不齐时反而显出一圈缺口。

贴片窗**不套毛玻璃**：DWM 的亚克力效果按窗口包围盒画，不认 region 裁出来的
形状，套上去四角外侧会冒出一圈深灰。

### 贴片底色为什么用渐变而不是纯色

Win11 任务栏是亚克力材质，颜色跟着壁纸走，而且**横向有明显渐变**。实测
通知区附近：

```
x=1700 → (209, 221, 221)
x=1850 → (216, 229, 228)
x=1900 → (224, 236, 233)
x=2000 → (230, 234, 234)
```

90 像素宽的贴片就横跨这段，差 8~20 级。填一个纯色，无论取哪个采样点，
总有一条边对不上 —— 肉眼就是「任务栏上一块淡淡的方印子」。

所以 `winui.taskbar_background_profile()` 沿贴片**自己的横向区间**采
7 个点（纵向取贴片上方/下方那两条空白，避开文字笔画），前端画成
`linear-gradient(to right, ...)`。

> **已知残余色差**：显示器色彩管理对窗口合成做的色彩变换与任务栏不是同
> 一条路径，同一个 8bit 值落到屏幕上会差 1~4 级。试过按实测差值做闭环补偿，
> 但那个变换既不是加性偏移、也不完全单调，迭代会在目标两侧来回跳（会越修
> 越花），所以**不补偿**。渐变采样点误差落在 1~2 级，正常视距下看不出边界。

### 「已运行」为什么以 5 秒为断点

光标停止移动或松开按键后，计时再平滑走满 5 秒才停。收段末端算到
`min(now, last_active + IDLE)`，`today()` 也封顶到此刻 —— 三处口径不一致
就是「数字先冻住、过几秒突然 +5、偶尔还往回跳」的成因。

### 主窗为什么不会漂

* 底边钉死在任务栏上沿（`y = bar_top - h - gap`），窗口只往上长，
  切换设备改变高度时底边不动；
* `x` 算出后锁进 `_fixed_x` 复用 —— 「按图标中心」与「按通知区中心」差 40 多
  像素，不锁的话每次点托盘图标都横向挪一次；
* 「已应用高度」与「前端上报高度」分开存，避免首帧误报把窗口压塌。

## 已知限制

* 只支持走 USB 接收器的 HID++ 2.0 设备，蓝牙直连与有线直连未对接。
* 贴片窗是**任务栏的子窗口** —— explorer 一重启它就会被连带销毁。程序会
  自动检测并重建（见 `docs/REFERENCE.md`），但重建的那一两秒里贴片是空的。
* 只有电压特性（`0x1001`）的设备显示「不支持」—— 电压换算百分比各机型不一致，
  硬换算出来的数字是骗人的。
* 使用时长统计的是**全系统的键鼠动作**，不是某只设备自己的传感器数据
  （Windows 不提供后者）。
* 键盘 / 耳机 / 手柄的分类与图标已就位，但**尚未用真机验证**枚举与命名；
  接入后如果分类不对，改 `devices.KIND_HINTS` 即可。
* 装了搜狗输入法时，它注入到 WebView2 的 TSF 组件会往**进程工作目录**写
  `debug.log`（内容是 `SGRenderLog`，与本程序无关）。本程序启动时已把 CWD
  挪到 `%LOCALAPPDATA%\WirelessStatus\runtime\`，所以 exe 旁边不会出现这个文件。
